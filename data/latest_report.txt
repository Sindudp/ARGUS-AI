INVESTIGATION
**Threat 1 – Credential‑spray → Compromised admin → Lateral ransomware spread (G1 ↔ G2 ↔ G7)**  
- **Attack chain:** Brute‑force login attempts (T1110) from 192.168.1.26 → successful admin login (T1078) → remote‑service lateral movement to another host (T1021) where ransomware files (*.argus_locked) encrypt ~15 k files.  
- **Likely attacker type:** Likely a credential‑based attacker exploiting a weak admin password; no attribution can be drawn from the logs.  
- **Possible related CVE:** *No strongly matching CVE found* (no application‑exploit description).  
- **Root cause:** Inadequate password‑policy / lack of account‑lockout allowing password‑spraying, and unrestricted remote‑service access that let the compromised account move laterally.  

**Threat 2 – Ransomware execution (G6)**  
- **Attack chain:** Process “ransomware.exe” observed on a host (T1486) – early ransomware indicator before mass encryption.  
- **Likely attacker type:** Cannot be determined from the logs.  
- **Possible related CVE:** *No strongly matching CVE found* (no exploit description).  
- **Root cause:** Execution of a known ransomware binary, likely delivered by prior lateral movement (see Threat 1) and not blocked by endpoint controls.  

**Threat 3 – Staged large‑volume data exfiltration (G3 ↔ G4)**  
- **Attack chain:** Small test transfer (≈42 KB) from 192.168.1.24 to external 185.220.101.45 (T1020) → followed minutes later by a 424 MB transfer to the same destination (T1041) indicating staged exfiltration.  
- **Likely attacker type:** Likely an attacker who already has internal foothold; attribution cannot be derived.  
- **Possible related CVE:** *No strongly matching CVE found* (no application‑exploit description).  
- **Root cause:** Insufficient outbound traffic monitoring / lack of data‑loss‑prevention controls that allowed large, unsanctioned transfers.  

**Threat 4 – SQL‑injection against file‑transfer web app (G8)**  
- **Attack chain:** External IP sends a SQL‑injection payload against the internal web service (T1190).  
- **Likely attacker type:** Likely an external opportunistic attacker probing the public‑facing application.  
- **Possible related CVE:** **CVE‑2023‑35708** – Critical SQL‑injection vulnerability in MOVEit Transfer that permits unauthenticated access.  
- **Root cause:** Unpatched MOVEit Transfer (or similar) web application exposing a known SQL‑injection flaw; lack of WAF or input validation allowed the exploit attempt.  

PLAYBOOKS
**Playbook – Threat 1 – Credential‑spray → Compromised admin → Lateral ransomware spread (G1 ↔ G2 ↔ G7)**  

*Management summary* – A brute‑force campaign from internal host **192.168.1.26** succeeded, giving the attacker an admin session that was used to move laterally and begin ransomware encryption on a second server. Immediate containment is required to stop further spread and protect data.  

*Immediate actions*  
1. Isolate **192.168.1.26** from the network.  
2. Disable the compromised **admin** account and force password reset.  

*Containment steps*  
1. Pull Windows Security logs from 192.168.1.26. **Owner:** SOC Analyst – **Time:** 30 min  
2. Capture NetFlow for the lateral‑movement session. **Owner:** Network Engineer – **Time:** 45 min  
3. Block remote‑service ports (RDP/SMB) for the compromised account on all assets. **Owner:** IAM Team – **Time:** 1 h  
4. Scan the target host (where *.argus_locked* appeared) for ransomware artifacts. **Owner:** Endpoint Team – **Time:** 2 h  
5. Remove ransomware binaries and restore encrypted files from clean backups. **Owner:** Backup Admin – **Time:** 4 h  
6. Conduct a password‑policy audit and enable account lockout after 5 failures. **Owner:** Security Ops – **Time:** 8 h  

---  

**Playbook – Threat 2 – Ransomware execution (G6)**  

*Management summary* – The process **ransomware.exe** was observed running on a workstation, indicating an early ransomware stage before mass encryption. Rapid isolation and eradication are needed to prevent file loss.  

*Immediate actions*  
1. Isolate the infected workstation from all network segments.  
2. Terminate the **ransomware.exe** process and delete the executable.  

*Containment steps*  
1. Acquire a memory dump for forensic analysis. **Owner:** DFIR Analyst – **Time:** 30 min  
2. Identify any C2 domains or IPs contacted. **Owner:** Threat Intel – **Time:** 45 min  
3. Run a full endpoint AV/EDR scan and quarantine malicious files. **Owner:** Endpoint Team – **Time:** 1 h  
4. Restore critical files from the latest clean backup. **Owner:** Backup Admin – **Time:** 3 h  
5. Apply application‑allow list to block execution of unknown binaries. **Owner:** Hardening Team – **Time:** 4 h  
6. Review recent admin logins for signs of credential misuse. **Owner:** SOC Lead – **Time:** 6 h  

---  

**Playbook – Threat 3 – Staged large‑volume data exfiltration (G3 ↔ G4)**  

*Management summary* – Host **192.168.1.24** first sent a tiny test file, then a 424 MB payload to external address **185.220.101.45**, indicating staged data theft. Blocking the outbound channel and investigating the host are top priorities.  

*Immediate actions*  
1. Block all outbound traffic from 192.168.1.24 to 185.220.101.45 at the perimeter firewall.  
2. Isolate 192.168.1.24 from the corporate LAN.  

*Containment steps*  
1. Export NetFlow and proxy logs for the 192.168.1.24 session. **Owner:** Network Ops – **Time:** 30 min  
2. Capture a forensic image of the host’s disk. **Owner:** DFIR Analyst – **Time:** 1 h  
3. Identify the data categories transferred (e.g., PII, IP). **Owner:** Data Owner – **Time:** 2 h  
4. Deploy a DLP rule to block similar outbound transfers. **Owner:** DLP Engineer – **Time:** 3 h  
5. Apply an outbound‑traffic ACL denying unknown external destinations. **Owner:** Firewall Admin – **Time:** 4 h  
6. Notify Legal/Compliance and begin breach‑notification process if required. **Owner:** GRC Lead – **Time:** 6 h  

---  

**Playbook – Threat 4 – SQL‑injection against public‑facing web app (G8)**  

*Management summary* – An external IP attempted a SQL‑injection against the internal web service, a clear exploitation attempt that could expose database contents. Immediate perimeter blocking and web‑application hardening are required.  

*Immediate actions*  
1. Block the attacking external IP at the perimeter firewall.  
2. Enable a Web‑Application Firewall (WAF) rule to filter SQL‑i payloads.  

*Containment steps*  
1. Pull the web server access logs for the offending request. **Owner:** Web Ops – **Time:** 30 min  
2. Verify whether the vulnerable component (e.g., MOVEit) is patched. **Owner:** Patch Management – **Time:** 45 min  
3. Apply the missing patch (CVE‑2023‑35708) or upgrade the application. **Owner:** Application Owner – **Time:** 2 h  
4. Configure WAF to block known injection patterns permanently. **Owner:** Security Engineer – **Time:** 1 h  
5. Conduct a code review of input‑validation routines. **Owner:** DevSec Team – **Time:** 4 h  
6. Perform a vulnerability scan to confirm remediation. **Owner:** Red Team – **Time:** 6 h
